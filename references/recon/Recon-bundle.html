asn & netblock enumeration

expandir a superficie de ataque alem dos dominios conhecidos. descobrir ranges de ip, sistemas autonomos, e infraestrutura de rede do alvo. util pra achar shadow it, servidores esquecidos, e ips fora do escopo de dns.

1. asn discovery

# achar o asn a partir do dominio
dig A alvo.com +short | head -1 | xargs whois | grep -iE "origin|originas|aut-num" | head -5

# bgp.he.net
curl -s "https://api.bgpview.io/search?query_term=alvo.com" | jq '.data.ipv4_prefixes[].asn.asn' | sort -u

# amass intel (busca asn por organizacao)
amass intel -org "Empresa Alvo" -o asn_intel.txt
amass intel -asn 12345 -o asn_ips.txt

# asnmap (projectdiscovery)
asnmap -d alvo.com -silent
asnmap -org "Google" -silent

# hackertarget api
curl -s "https://api.hackertarget.com/aslookup/?q=alvo.com"

2. ip range discovery

# whois (rir: arin, ripe, apnic, lacnic, afrinic)
whois $(dig +short alvo.com | head -1) | grep -iE "inetnum|netrange|cidr|route:" | head -10

# bgpview api
curl -s "https://api.bgpview.io/search?query_term=alvo.com" | jq -r '.data.ipv4_prefixes[].prefix' | sort -u

# traceroute (ips intermediarios da infra)
traceroute -n alvo.com
tcptraceroute alvo.com 443

# shodan (se tiver api key)
shodan search "org:'Empresa Alvo'" --fields ip_str,port,org

# censys
censys search 'services.tls.certificates.leaf_data.subject_dn:"alvo.com"' | jq '.[].ip'

expandir ranges a partir de ips conhecidos

# pegar todos os ips do dominio
dig A alvo.com +short > ips.txt
dig MX alvo.com +short | awk '{print $NF}' | while read mx; do dig A "$mx" +short; done >> ips.txt
dig NS alvo.com +short | while read ns; do dig A "$ns" +short; done >> ips.txt

# pra cada ip, consultar bgpview
sort -u ips.txt | while read ip; do
  curl -s "https://api.bgpview.io/ip/$ip" | jq -r '.data.prefixes[].prefix' 2>/dev/null
done | sort -u > ip_ranges.txt

3. reverse dns em massa

# reverse dns nos ranges
cat ip_ranges.txt | while read range; do
  prips "$range" 2>/dev/null | xargs -I{} -P 100 host {} 2>/dev/null | grep "pointer" | awk '{print $NF}'
done | sort -u > ptr_records.txt

# dnsx (mais rapido)
cat ip_ranges.txt | prips - | dnsx -ptr -resp-only -r resolvers.txt -o dnsx_ptr.txt

# filtrar dominios do alvo
cat dnsx_ptr.txt | grep "alvo.com" | sort -u
💡 ptr records sao ouro

reverse dns as vezes revela nomes de servidores internos, funcoes (db01, backup, vpn, monitor), e dominios que nao estao no dns publico.

4. scan nos ranges descobertos

# top 100 portas (rapido)
nmap -iL ip_ranges.txt --top-ports 100 -T4 -oA range_scan

# so servicos web (menos barulhento)
nmap -iL ip_ranges.txt -p 80,443,8080,8443,8000,8888,3000,5000,9000 -T4 --open -oA web_scan

# rustscan (mais rapido)
rustscan -a "$(cat ip_ranges.txt | head -10)" --ulimit 5000 -- -sV -oA rustscan_web

# httpx nos ips (titulos e certificados)
cat live_ips.txt | httpx -silent -title -status-code -tech-detect

# screenshot massivo
cat live_ips.txt | aquatone -out screenshots/

7. workflow completo

#!/bin/bash
DOMAIN=$1
OUTDIR="recon/$DOMAIN/netblock"
mkdir -p "$OUTDIR"

echo "[*] descobrindo ips do dominio..."
dig A "$DOMAIN" +short > "$OUTDIR/domain_ips.txt"
dig MX "$DOMAIN" +short | awk '{print $NF}' | while read mx; do dig A "$mx" +short; done >> "$OUTDIR/domain_ips.txt"
sort -u "$OUTDIR/domain_ips.txt" -o "$OUTDIR/domain_ips.txt"

echo "[*] buscando asn e ranges..."
sort -u "$OUTDIR/domain_ips.txt" | while read ip; do
  curl -s "https://api.bgpview.io/ip/$ip" | jq -r '.data.prefixes[].prefix' 2>/dev/null
done | sort -u > "$OUTDIR/ip_ranges.txt"

echo "[*] reverse dns nos ranges..."
cat "$OUTDIR/ip_ranges.txt" | while read range; do
  prips "$range" 2>/dev/null | xargs -P 50 -I{} host {} 2>/dev/null | grep "pointer" | awk '{print $NF}'
done | sort -u > "$OUTDIR/ptr_records.txt"

echo "[*] filtrando dominios do alvo..."
grep -i "$DOMAIN" "$OUTDIR/ptr_records.txt" > "$OUTDIR/target_ptrs.txt"

echo "[+] ranges: $(wc -l < "$OUTDIR/ip_ranges.txt")"
echo "[+] ptr records: $(wc -l < "$OUTDIR/ptr_records.txt")"
echo "[+] ptr do alvo: $(wc -l < "$OUTDIR/target_ptrs.txt")"
echo "[done] resultados em $OUTDIR/"

[!warning] ranges de CDN (Cloudflare/Akamai/AWS) nao sao do alvo. confirmar com whois antes de atacar. ranges compartilhados sao fora de escopo em BB

[!tip] ASN via SPF: dig txt alvo.com -> achar include: -> resolver IPs do include pra descobrir infra de email

8. favicon hash fingerprinting

fingerprint de servidor pelo hash do favicon (ico). mmh3 hash + shodan http.favicon.hash pra achar origin atras de CDN e clusterizar hosts do mesmo alvo.

# calcular hash mmh3 do favicon
python3 -c "import mmh3,requests,codecs; r=requests.get('https://alvo.com/favicon.ico'); hash=mmh3.hash(codecs.encode(r.content,'base64')); print(hash)"

# buscar no shodan todos os hosts com mesmo favicon
shodan search http.favicon.hash:HASH --fields ip_str,port,hostnames,org

9. SPF/DKIM como fonte de infra

registros SPF revelam servidores de email autorizados. includes apontam pra SendGrid, Mailgun, etc — as vezes do alvo.

dig txt alvo.com +short | grep "include:" | sed 's/.*include://; s/ //g'
# resolver IPs do include
dig txt alvo.com +short | grep -oP 'include:\K[^ ]+' | while read d; do dig A "$d" +short; done

enumerar buckets S3, azure blob, gcp storage, e apps serverless baseados no nome do alvo.

banner scanning

tecnica de reconhecimento ativo que consiste em conectar nos servicos do alvo pra ler as mensagens de boas-vindas (banners) e identificar versoes de software, sistema operacional e tecnologias em uso.

metadado valor
tipo de reconhecimento ativo
nivel de ruido medio-baixo
ℹ por que funciona

a maioria dos servicos de rede (ssh, ftp, smtp, http) envia um banner de identificacao quando um cliente conecta. como a conexao parece uma conexao normal de cliente, raramente levanta alertas.

1. leitura de banner com netcat e telnet

a forma mais classica. funciona em qualquer servico que responda em texto claro (sem tls).

# banner de um servico http na porta 80
nc -v $TARGET 80

# mesma coisa com telnet
telnet $TARGET 80

# pra servico smtp
nc -v $TARGET 25

# ftp
nc -v $TARGET 21
💡 dica pratica

depois de conectar no http, digite HEAD / HTTP/1.0 e aperte enter duas vezes pra receber o header de resposta com o banner do servidor web.

2. servicos com tls/ssl

pra servicos criptografados, netcat e telnet nao funcionam. use openssl ou ncat com suporte a ssl.

# openssl pra https na porta 443
openssl s_client -connect $TARGET:443 -quiet

# ncat com ssl
ncat --ssl $TARGET 443

3. banner grabbing automatizado com nmap

o nmap tem scripts especificos pra pegar banners de forma massiva.

# banner grab simples em portas especificas
nmap -sV --script=banner -p 21,22,25,80,110,443 $TARGET

# scan de versao agressivo (mais preciso, mais barulhento)
nmap -sV --version-intensity 5 -p- $TARGET

# scan rapido top 1000 portas com deteccao de versao
nmap -sV -T4 $TARGET

[!tip] nmap -sV –version-intensity 5 para fingerprint profundo. –version-intensity 9 e maximo mas muito barulhento

4. identificacao de tecnologias web

ferramentas especializadas em identificar tecnologias de aplicacoes web (frameworks, cms, servidores).

# whatweb - fingerprint de tecnologias web
whatweb $TARGET

# whatweb agressivo (mais requests, mais info)
whatweb -a 3 $TARGET

# curl pra ler headers http manualmente
curl -sI http://$TARGET

# curl com follow redirect
curl -sIL http://$TARGET

# httpx (projectdiscovery) - alternativa moderna ao whatweb
httpx -u alvo.com -tech-detect -status-code -title
ℹ httpx vs whatweb

httpx (projectdiscovery) e mais rapido e suporta pipeline com outras ferramentas pd. whatweb e mais antigo mas ainda funciona. httpx e a opcao preferida pra automacao moderna.

5. ferramentas especificas de banner

# dnsver.pl - versao do bind em servidores dns
./dnsver.pl -t 50 -v $TARGET

# smbclient pra versao do smb
smbclient -L //$TARGET -N

# smtp-user-enum pra enumerar usuarios via smtp
smtp-user-enum -M VRFY -U users.txt -t $TARGET

6. interpretacao de resultados

depois de coletar os banners, a analise e simples:

  1. identifique o software e a versao exata (ex: Apache/2.4.49, OpenSSH_8.2p1)
  2. pesquise no exploit-db ou searchsploit por vulnerabilidades conhecidas
  3. compare com banners conhecidos pra confirmar o sistema operacional
# pesquisa local no exploit-db
searchsploit apache 2.4.49
searchsploit openssh 8.2

[!warning] banners sao customizaveis. admin pode esconder versao real. sempre cross-referenciar com fingerprint tcp e tls

7. favicon hash - identificar mesmo servidor across domains

o hash do favicon (mmh3) e unico por aplicacao. shodan indexa favicon hashes. permite identificar o mesmo servidor em multiplos dominios.

# calcular favicon hash com python3
python3 -c "import mmh3,requests,codecs; r=requests.get('https://alvo.com/favicon.ico'); print(mmh3.hash(codecs.encode(r.content,'base64')))"

# buscar no shodan pelo favicon hash
# shodan: http.favicon.hash:HASH
# exemplo: shodan search "http.favicon.hash:-1234567890"

[!tip] favicon hash e util pra identificar paineis admin (jenkins, grafana, kibana) mesmo quando o banner http nao revela nada.

8. jarm - tls server fingerprint

jarm (salesforce) gera um fingerprint do servidor tls baseado em comportamento. mais preciso que banner porque nao pode ser customizado.

# gerar jarm fingerprint
python3 jarm.py alvo.com 443

# com output json
python3 jarm.py alvo.com 443 -j

# buscar no censys por jarm
# censys: services.jarm.fingerprint: "HASH"

[!info] jarm identifica servidor e versao mesmo quando banner e customizado. censys indexa jarm de todos hosts tls. permite encontrar outros servidores do mesmo alvo.

9. http header ordering - ordem dos headers identifica web server

a ordem dos headers http varia por servidor: nginx, apache, iis ordenam diferente. nao pode ser customizado facil.

# ver ordem dos headers
curl -sI alvo.com | head -20

# nginx tipicamente envia: server, date, content-type, content-length
# apache tipicamente envia: date, server, last-modified, etag, accept-ranges, content-length
# iis tipicamente envia: content-length, content-type, server, x-powered-by

[!tip] header ordering e um fingerprint passivo. o servidor nao sabe que tu ta analisando a ordem. combina com jarm pra confirmar.

10. service-specific probes - banners por protocolo

cada protocolo tem seu jeito de revelar versao. vale rodar probes especificos alem do scan generico.

# smb - versao do samba/windows
smbclient -L //$TARGET -N

# rdp - enumerar metodos de encriptacao
nmap --script rdp-enum-encryption -p 3389 $TARGET

# ssh - banner exchange (versao do openssh)
nc $TARGET 22

# mysql - version packet
nc $TARGET 3306

# ftp - banner de boas-vindas
nc $TARGET 21

# smtp - banner e capabilities
nc $TARGET 25
# EHLO alvo.com

[!warning] alguns probes geram log no servidor (ex: smb, smtp). sempre considere stealth vs completude.

checklist rapido

  • nc -v $TARGET porta (banner manual)
  • openssl s_client -connect $TARGET:443 (tls)
  • nmap -sV –version-intensity 5 (scan versao)
  • whatweb / httpx -tech-detect (fingerprint web)
  • curl -sI | head -20 (header ordering)
  • python3 jarm.py (tls fingerprint)
  • favicon hash mmh3 (identificar across domains)
  • smbclient -L (smb)
  • nmap –script rdp-enum-encryption (rdp)
  • nc $TARGET 22 (ssh banner)
  • searchsploit (buscar exploits da versao)
  • cross-referenciar banner + jarm + tcp fingerprint

consulta de certificado tls

tecnica passiva de reconhecimento que usa os logs publicos de certificate transparency (ct) pra descobrir subdominios de um alvo. como os certificados tls sao registrados publicamente, qualquer subdominio que tenha um certificado emitido fica visivel sem precisar tocar no alvo.

metadado valor
tipo de reconhecimento passivo
nivel de ruido 0
ℹ o que e certificate transparency

ct e um sistema publico de logs onde todas as autoridades certificadoras (cas) registram os certificados que emitem. sites como crt.sh indexam esses logs, permitindo que qualquer pessoa consulte quais subdominios tem certificado tls emitido.

1. crt.sh via curl

a forma mais rapida e direta. crt.sh e gratuito e nao exige autenticacao.

# consulta basica em json
curl -s "https://crt.sh/?q=alvo.com&output=json" | jq .

# formato de tabela legivel (timestamp, common name, issuer)
curl -s "https://crt.sh/?q=alvo.com&output=json" | jq -r '.[] | [.entry_timestamp, .common_name, .issuer_name] | @tsv' | column -t -s $'\t'

# extrair apenas subdominios unicos (o mais util)
curl -s "https://crt.sh/?q=alvo.com&output=json" | jq -r '.[].common_name, .[].name_value' | sort -u

# filtrar wildcards e limpar resultados
curl -s "https://crt.sh/?q=%.alvo.com&output=json" | jq -r '.[].name_value' | sed 's/\*\.//g' | sort -u
💡 dica pratica

o % no parametro q funciona como wildcard. use %.alvo.com pra pegar subdominios de todos os niveis.

💡 tlsx (projectdiscovery)

tlsx -u alvo.com -silent. fire-hose mode continua streamando certificados novos em near-real-time. mais rapido que curl + crt.sh.

2. openssl pra inspecao direta

se voce quiser inspecionar o certificado de um servidor especifico (e nao buscar em logs publicos):

# ver o certificado completo de um servidor
openssl s_client -connect alvo.com:443 -servername alvo.com 2>/dev/null | openssl x509 -noout -text

# extrair apenas o subject e subject alt names (subdominios no certificado)
openssl s_client -connect alvo.com:443 -servername alvo.com 2>/dev/null | openssl x509 -noout -text | grep -A1 "Subject Alternative Name"

# extrair apenas o common name
openssl s_client -connect alvo.com:443 -servername alvo.com 2>/dev/null | openssl x509 -noout -subject

# enumeracao passiva de subdominios (usa crt.sh + varias outras fontes)

# modo silencioso (so subdominios, sem banner)
subfinder -d alvo.com -silent

5. Censys

busca de cert mais confiavel que crt.sh pra volume alto. api mais estavel.

# busca de certificados por dominio
censys search 'services.tls.certificates.leaf_data.subject_dn:"alvo.com"' | jq '.[].ip'

# buscar todos os certs com SAN do alvo

💡 censys vs crt.sh

censys e mais estavel que crt.sh pra volume alto. free tier = 250 queries/mes. pra volume maior, assinatura.

6. SAN extraction

subdominios hidden no certificado que nao aparecem em crt.sh. extrair diretamente do cert do servidor.

# extrair SANs do certificado do servidor
openssl s_client -connect alvo.com:443 -servername alvo.com 2>/dev/null \
  | openssl x509 -noout -text \
  | grep -A1 "Subject Alternative Name"
💡 SANs escondidos

alguns certificados tem dezenas de SANs. comparar com crt.sh pra achar subdominios que nao foram indexados ainda.

7. CT log monitoring

alertar quando alvo emite cert novo (novo subdominio). monitoramento continuo.

# certspotter - watch mode (alerta em tempo real)
certspotter -domain alvo.com -watch

# tlsx - fire-hose mode (stream de certs novos)
tlsx -u alvo.com -silent -mode fire-hose

# chaos API com cronjob
# 0 */6 * * * chaos -d alvo.com -silent | diff old_subs.txt - | grep ">" | notify
⚠ crt.sh instavel

crt.sh e instavel e rate-limited sob carga. ter certspotter ou tlsx como fallback.

consulta de dns

tecnicas de reconhecimento via dns pra descobrir subdominios, servidores de email, nameservers e outros registros associados a um dominio alvo. a maioria dessas consultas e passiva e nao gera ruido.

metadado valor
tipo de reconhecimento passivo
nivel de ruido 0

1. ferramentas nativas do sistema

host

# consultar toda a base dns de um dominio
host -l -v -t any alvo.com

# registros especificos
host -t mx alvo.com     # servidores de email
host -t ns alvo.com     # nameservers
host -t txt alvo.com    # registros txt (spf, dkim, etc)
host -t a alvo.com      # endereco ipv4
host -t aaaa alvo.com   # endereco ipv6
host -t cname alvo.com  # aliases

dig

# consulta completa
dig -t any alvo.com

# registros especificos
dig -t mx alvo.com
dig -t ns alvo.com
dig -t txt alvo.com

# consultar usando um nameserver especifico
dig @8.8.8.8 alvo.com

# consulta reversa (ip -> dominio)
dig -x 192.168.1.1

# transferencia de zona (se o servidor permitir - raro mas muito valioso)
dig axfr alvo.com @ns1.alvo.com

# trace - mostra o caminho completo de resolucao (root -> TLD -> authoritative)
dig +trace alvo.com

[!tip] dig +trace mostra o caminho completo de resolucao (root -> TLD -> authoritative). util pra entender a infra dns do alvo

💡 transferencia de zona

se o servidor dns estiver mal configurado e permitir zone transfer (axfr), voce recebe TODOS os registros dns do dominio de uma vez. sempre tente isso primeiro.

[!warning] axfr (zone transfer) e logado no dns server. em pentest real usar so com autorizacao. e raro mas muito valioso quando funciona

nslookup

# consulta basica
nslookup alvo.com

# consulta interativa pra multiplos registros
nslookup
> set type=any
> alvo.com
> set type=mx
> alvo.com

2. ferramentas especializadas

dnsrecon

# enumeracao completa automatizada
dnsrecon -d alvo.com

# tentativa de zone transfer
dnsrecon -d alvo.com -t axfr

# brute-force de subdominios
dnsrecon -d alvo.com -t brt -D /usr/share/wordlists/subdomains.txt

fierce

# enumeracao dns com brute-force integrado
fierce --domain alvo.com

# com wordlist customizada
fierce --domain alvo.com --subdomain-file wordlist.txt

amass

# enumeracao passiva (so consultas publicas, sem contato com o alvo)
amass enum -passive -d alvo.com

# enumeracao ativa (mais completa, mais barulhenta)
amass enum -active -d alvo.com -o resultados.txt

# visualizar o que foi encontrado
amass viz -d3 -d alvo.com
ℹ amass vs outras ferramentas

o amass combina dezenas de fontes publicas (shodan, censys, virustotal, etc) numa unica ferramenta. e a melhor opcao pra enumeracao passiva em larga escala.

dnsx (projectdiscovery)

alternativa moderna ao dig em massa. escrita em go, suporta pipeline com outras ferramentas pd.

# resolver subdominios em massa
dnsx -d alvo.com -silent

# reverse dns (ptr)
dnsx -ptr -ip 192.168.1.0/24 -silent

# zone transfer
dnsx -d alvo.com -axfr -silent

# com asn info
dnsx -d alvo.com -asn -silent

4. dns over https (doh) - queries stealth

queries dns via https bypassam monitoramento de dns local. o destino ve so uma conexao https pra cloudflare/google.

# query doh via curl (cloudflare)
curl -H 'accept: application/dns-json' 'https://cloudflare-dns.com/dns-query?name=alvo.com&type=A'

# query doh via curl (google)
curl 'https://dns.google/resolve?name=alvo.com&type=A'

# batch de subdominios via doh
for sub in www mail admin vpn; do
  curl -s -H 'accept: application/dns-json' "https://cloudflare-dns.com/dns-query?name=$sub.alvo.com&type=A" | jq -r '.Answer[0].data'
done

[!info] doh e util quando tu quer evitar que o alvo ou isp veja tuas queries dns. o trafego parece https normal.

5. dnssec - verificar misconfig

dnssec adiciona assinaturas criptograficas aos registros dns. misconfig pode permitir enumeracao de zone.

# verificar se dnssec esta ativo
dig +dnssec alvo.com +short

# verificar rrsig
dig alvo.com RRSIG +dnssec +short

# verificar dnskey
dig alvo.com DNSKEY +dnssec +short

[!warning] dnssec mal configurado pode vazar informacoes. se o nsec3 nao estiver configurado, e possivel enumerar a zone inteira.

6. dns cache snooping

descobrir se um resolver dns ja tem cacheado um dominio = alguem acessou recentemente.

# query sem recursao (norecurse). se responder, esta cacheado
dig @resolver_alvo alvo.com +norecurse

# batch de dominios pra checar
for domain in facebook.com google.com github.com; do
  result=$(dig @resolver_alvo $domain +norecurse +short)
  if [ -n "$result" ]; then
    echo "[CACHED] $domain -> $result"
  fi
done

[!tip] cache snooping revela quais sites os usuarios da rede acessaram. util em pentest interno pra entender comportamento.

7. nsec walking - dnssec zone enumeration

quando dnssec usa nsec (nao nsec3), cada registro nsec aponta pro proximo nome na zone. permite enumerar todos os registros.

# comecar nsec walking
dig alvo.com NSEC +dnssec +short

# cada nsec aponta pro proximo nome - seguir a cadeia
# ferramenta automatizada: nsecwalker ou ldns-walk
ldns-walk alvo.com

# alternativa manual
dig alvo.com NSEC +dnssec +short
# output: alvo.com. NSEC www.alvo.com
dig www.alvo.com NSEC +dnssec +short
# output: www.alvo.com. NSEC mail.alvo.com
# repetir ate voltar ao inicio

[!warning] nsec walking so funciona com nsec (nao nsec3). nsec3 usa hashes, nao nomes em texto claro. sites modernos usam nsec3 pra evitar isso.

  • host -t mx / -t ns / -t txt / -t a (registros basicos)
  • dig +trace (caminho de resolucao)
  • dig axfr @ns1.alvo.com (zone transfer)
  • dnsx -d alvo.com (resolver em massa)
  • dnsx -ptr -ip (reverse dns)
  • amass enum -passive (enumeracao passiva)
  • curl doh cloudflare (queries stealth)
  • dig +dnssec (verificar dnssec)
  • dig @resolver +norecurse (cache snooping)
  • ldns-walk (nsec walking se dnssec com nsec)
  • dnsdumpster / securitytrails (recursos online)

descoberta de hosts numa rede interna

tecnicas pra identificar quais maquinas estao ativas dentro de uma rede local. essencial como primeiro passo apos conseguir acesso a uma rede interna durante um pentest ou ctf.

1. descoberta passiva (zero ruido)

essas tecnicas nao enviam nenhum pacote pra rede. voce so escuta o trafego que ja esta rolando.

netdiscover (modo passivo)

# escutar o trafego arp e mapear hosts sem enviar nada
netdiscover -p

# especificar interface
netdiscover -p -i eth0

p0f (fingerprint passivo)

# identificar sistemas operacionais pelo trafego de rede
p0f -i eth0 -p -o /tmp/p0f.log
ℹ quando usar modo passivo

use quando voce quer evitar deteccao total. ideal pra ambientes com ids/ips monitorando. a desvantagem e que so descobre hosts que estao gerando trafego no momento.

2. descoberta ativa - camada 2 (arp)

arp funciona dentro do mesmo segmento de rede (broadcast domain). mais confiavel que icmp porque arp nao e filtrado por firewalls de host.

arp-scan

# scan de toda a sub-rede
sudo arp-scan -l

# especificar range e interface
sudo arp-scan -I eth0 192.168.1.0/24

# scan em multiplas redes
sudo arp-scan 10.0.0.0/24 172.16.0.0/24

[!warning] arp-scan precisa de root. sem root cai pra icmp ou tcp probe

arping (um host por vez)

# loop pra varrer um /24
for i in $(seq 1 254); do arping -c 1 -w 1 192.168.1.$i 2>/dev/null | grep "reply"; done

nmap arp scan

# nmap so com arp (sem port scan)
sudo nmap -sn -PR 192.168.1.0/24

[!tip] nmap -sn –disable-arp-ping forca icmp quando arp nao funciona (cross-subnet). util quando tu ta em rede diferente do alvo

3. descoberta ativa - camada 3 (icmp/ping)

funciona entre sub-redes diferentes mas pode ser bloqueado por firewalls.

ping sweep com bash

# loop simples pra /24
for i in $(seq 1 254); do ping -c 1 -W 1 10.10.10.$i 2>/dev/null | grep "from" & done; wait

# salvar hosts vivos em arquivo
for i in $(seq 1 254); do ping -c 1 -W 1 10.10.10.$i 2>/dev/null | grep "from"; done > live_hosts.txt

fping (mais rapido que ping loop)

# scan de sub-rede inteira com fping
fping -a -g 192.168.1.0/24 2>/dev/null

# com output de hosts vivos em arquivo
fping -a -g 192.168.1.0/24 2>/dev/null > alive.txt

nmap icmp sweep

# ping sweep padrao
sudo nmap -sn -PE 192.168.1.0/24

# com multiplas tecnicas (icmp echo + timestamp + tcp syn/ack)
sudo nmap -sn -PE -PP -PS21,22,25,80,443 -PA80,443 192.168.1.0/24

4. descoberta avancada (sem icmp)

quando icmp esta bloqueado, use scans tcp/udp pra descobrir hosts.

# tcp syn em portas comuns (descobre hosts mesmo com icmp bloqueado)
sudo nmap -sn -PS22,80,443,445,3389 10.10.10.0/24

# tcp ack (util pra contornar firewalls stateless)
sudo nmap -sn -PA80,443 10.10.10.0/24

# udp em portas comuns
sudo nmap -sn -PU53,161,137 10.10.10.0/24

5. enumeracao windows (netbios/smb)

em redes windows, protocolos especificos revelam muita informacao.

# nbtscan - nomes netbios da rede
nbtscan 192.168.1.0/24

# enum4linux - enumeracao completa de smb
enum4linux -a 192.168.1.0/24

# responder em modo analise (escuta sem atacar)
sudo responder -I eth0 -A

naabu (projectdiscovery)

alternativa moderna ao nmap focada em port scan rapido. escrita em go, mais veloz que nmap pra descoberta em massa.

# scan top 1000 portas de uma lista de hosts
naabu -list hosts.txt -top-ports 1000 -silent

# scan de uma sub-rede
naabu -host 192.168.1.0/24 -silent

# scan com deteccao de servico
naabu -host 192.168.1.0/24 -sV -silent
ℹ naabu vs nmap

naabu e mais rapido pra descoberta rapida de hosts e portas. nmap e mais completo pra fingerprinting e scripts nse. use naabu pra varredura inicial, nmap pra analise detalhada.

6. /proc/net/arp - descoberta instantanea em box comprometida

em uma maquina linux comprometida, o kernel mantem cache arp de todas as comunicacoes recentes. zero pacotes enviados.

# ler cache arp do kernel
cat /proc/net/arp | grep -v HWtype

# mostrar so ips e macs
cat /proc/net/arp | awk '{print $1, $4}' | grep -v "IP HW"

[!tip] /proc/net/arp mostra hosts que o alvo comunicou recentemente. nao e um scan completo, so o cache. mas e 100% silencioso.

7. ipv6 discovery

ipv6 quase nunca tem firewall configurado. vale sempre testar.

# descoberta ipv6 com rdisc6
rdisc6 eth0

# nmap ipv6 top 20 portas
nmap -6 --top-ports 20 fe80::1%eth0

# ping6 pra testar link-local
ping6 -c 3 fe80::1%eth0

# nmap ipv6 scan completo
nmap -6 -sV fe80::1%eth0

[!warning] ipv6 link-local (fe80::) requer especificar a interface com %eth0. ipv6 global (2001::) nao precisa.

8. dhcp sniffing - descobrir config de rede inteira

dhcp revela gateway, dns, netmask, domain name. util em box comprometida pra entender a topologia.

# escutar pacotes dhcp na interface
dhcpdump -i eth0

# alternativa: dhclient em modo debug
dhclient -d -v eth0

[!info] dhcp sniffing e passivo. so escuta. se tu precisar forcar, manda um dhcp request: dhclient -1 eth0.

9. responder modo analyze - mapeamento passivo

responder em modo analise (-a) escuta sem responder. mapeia smb, llmnr, mDNS, nbt-ns sem envenenar.

# modo analise - so escuta
sudo responder -I eth0 -A

# com output em arquivo
sudo responder -I eth0 -A -w responder.log

[!tip] responder -a e a primeira coisa a rodar em uma rede interna desconhecida. mapeia tudo sem gerar alertas de envenenamento.

checklist rapido

  • netdiscover -p (passivo, zero ruido)
  • arp-scan -l (se root, mesmo subnet)
  • nmap -sn -PR (arp, mesmo subnet)
  • nmap -sn -PE (icmp, cross-subnet)
  • fping -a -g (ping sweep rapido)
  • nmap -sn -PS22,80,443,445 (tcp probe, icmp bloqueado)
  • cat /proc/net/arp (box comprometida, zero pacotes)
  • rdisc6 / nmap -6 (ipv6, quase nunca tem firewall)
  • dhcpdump -i eth0 (sniffing dhcp)
  • responder -I eth0 -A (mapeamento passivo smb/llmnr/mdns)
  • nbtscan / enum4linux (rede windows)
  • naabu -list hosts.txt -top-ports 1000 (port scan rapido)

enumeracao de diretorios

tecnica de reconhecimento ativo que consiste em fazer brute-force de caminhos (paths) em um servidor web pra descobrir paginas, arquivos e diretorios ocultos que nao sao linkados publicamente.

1. dirb

a ferramenta mais simples. usa wordlist padrao se nenhuma for especificada.

# scan basico (wordlist padrao)
dirb http://$TARGET

# com wordlist customizada
dirb http://$TARGET /usr/share/wordlists/dirb/big.txt

# scan em https
dirb https://$TARGET

# ignorar certificado invalido
dirb https://$TARGET -o resultado.txt

2. gobuster

mais rapido que dirb, suporta multiplas threads. ideal pra wordlists grandes.

# modo de enumeracao de diretorios
gobuster dir -u http://$TARGET -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt

# com extensoes especificas
gobuster dir -u http://$TARGET -w wordlist.txt -x php,html,txt,bak,old,zip

# com threads e timeout customizados
gobuster dir -u http://$TARGET -w wordlist.txt -t 50 -timeout 10s

# filtrar por status code (ignorar 404)
gobuster dir -u http://$TARGET -w wordlist.txt -b 404,403

# modo vhost (descobrir virtual hosts)
gobuster vhost -u http://$TARGET -w subdomains.txt

# modo dns (brute-force de subdominios)
gobuster dns -d alvo.com -w subdomains.txt

3. ffuf (o mais flexivel)

o ffuf e o fuzzer mais versatil. funciona pra diretorios, parametros, headers e qualquer coisa que voce queira testar.

# fuzzing basico de diretorios
ffuf -u http://$TARGET/FUZZ -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt

# com extensoes
ffuf -u http://$TARGET/FUZZ -w wordlist.txt -e .php,.html,.txt,.bak

# filtrar por tamanho de resposta (remover falsos positivos)
ffuf -u http://$TARGET/FUZZ -w wordlist.txt -fs 4242

# filtrar por status code
ffuf -u http://$TARGET/FUZZ -w wordlist.txt -fc 404,403

# filtrar por quantidade de palavras na resposta
ffuf -u http://$TARGET/FUZZ -w wordlist.txt -fw 1

# fuzzing de parametros (ex: ?id=FUZZ)
ffuf -u "http://$TARGET/page.php?id=FUZZ" -w /usr/share/wordlists/seclists/Fuzzing/special-chars.txt

# fuzzing de subdominios via header host
ffuf -u http://$TARGET -w subdomains.txt -H "Host: FUZZ.alvo.com" -fc 301
💡 dica sobre ffuf

o ffuf e a melhor opcao quando voce precisa de controle fino sobre filtros. a flag -mc all mostra todos os status codes e dai voce vai filtrando com -fc ou -fs conforme identifica os padroes de falso positivo.

💡 ffuf recursivo

ffuf -recursion -depth 2 faz auto-recursive sem script. descobre subdiretorios automaticamente.

4. feroxbuster (recursivo por padrao)

escrito em rust, rapido e recursivo por padrao. descobre subdiretorios automaticamente.

# scan recursivo padrao
feroxbuster -u http://$TARGET

# com wordlist e extensoes
feroxbuster -u http://$TARGET -w wordlist.txt -x php,html,txt

# limitar profundidade de recursao
feroxbuster -u http://$TARGET -w wordlist.txt --depth 3

# com threads customizadas
feroxbuster -u http://$TARGET -w wordlist.txt -t 100

5. wordlists recomendadas

wordlist caminho uso
dirb common /usr/share/wordlists/dirb/common.txt scan rapido
dirbuster medium /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt padrao
seclists web /usr/share/seclists/Discovery/Web-Content/ colecao completa
raft large dirs /usr/share/seclists/Discovery/Web-Content/raft-large-directories.txt diretorios extenso
raft large files /usr/share/seclists/Discovery/Web-Content/raft-large-files.txt arquivos extenso
⚠ cuidado com brute-force

enumeracao de diretorios e barulhenta. em ambientes com waf (cloudflare, akamai), voce pode ser bloqueado. use -t baixo e considere um delay entre requests com --delay.

⚠ cloudflare ban

cloudflare ban em ~200 req/s com threads altas. usar -rate 150 ou -t 10 em targets com waf.

6. 403 como sinal

403 = existe, tentar bypass. o servidor confirma que o path existe mas bloqueia acesso.

# %2e (encoded .)
curl https://alvo.com/admin%2e

# ; (path delimiter)
curl https://alvo.com/admin;

# x-original-url header
curl -H 'X-Original-URL: /admin' https://alvo.com/

# x-forwarded-for localhost
curl -H 'X-Forwarded-For: 127.0.0.1' https://alvo.com/admin

# %20 (espaco no final)
curl https://alvo.com/admin%20

# ; no final
curl https://alvo.com/admin;
💡 403 e sinal positivo

403 confirma que o path existe. nunca descarte 403 como 404. sempre tentar bypass.

7. backup file patterns

arquivos de backup muitas vezes ficam acessiveis no servidor. extensaoes comuns: .bak, .old, ~, .swp, .tmp, .orig, .save, .backup.

# ffuf com extensoes de backup
ffuf -u https://alvo.com/FUZZ -w dirs.txt -e .bak,.old,.swp,.tmp,.orig

# gobuster com extensoes
gobuster dir -u https://alvo.com -w dirs.txt -x bak,old,swp,tmp,orig,save,backup

8. wordlist de JS

extrair paths de source maps e JS bundles. o JS contem referencias a endpoints que nao estao em wordlists padrao.

# extrair paths de arquivos JS
cat js_files.txt | while read url; do
  curl -s "$url" | grep -oP '["'\''\x60](/[^"'\''\x60]+)["'\''\x60]' | tr -d '"'\'''\x60' | sort -u
done > js_paths.txt

# usar como wordlist no ffuf
ffuf -u https://alvo.com/FUZZ -w js_paths.txt

9. API versioning

/v1/, /v2/, /api/v1/ como alvos separados. versoes antigas as vezes tem auth mais fraco ou endpoints depreciados.

# fuzzing de paths de API
ffuf -u https://alvo.com/api/FUZZ -w api_paths.txt

# testar versoes diferentes
ffuf -u https://alvo.com/v1/FUZZ -w api_paths.txt
ffuf -u https://alvo.com/v2/FUZZ -w api_paths.txt
⚠ versoes antigas

endpoints de API em versoes antigas (/v1/) as vezes mantem auth mais fraco ou bugs corrigidos em /v2/.

checklist rapido

  • rodar ffuf com wordlist padrao (raft-medium)
  • adicionar extensoes comuns (.php, .html, .txt, .bak)
  • ativar recursao (-recursion -depth 2)
  • filtrar falsos positivos por tamanho (-fs) ou status (-fc)
  • testar bypass em todos os 403
  • fuzzar arquivos de backup (.bak, .old, .swp)
  • extrair paths de JS bundles
  • fuzzar endpoints de API (/api/, /v1/, /v2/)
  • ajustar rate/threads em targets com WAF

enumeracao ldap

tecnicas de enumeracao do servico ldap (portas 389/636) pra extrair informacoes de um active directory: usuarios, grupos, politicas de senha, spns e mais. essencial em qualquer pentest de ambiente windows corporativo.

1. scan inicial com nmap

primeiro passo e confirmar que ldap esta aberto e rodar scripts nse de enumeracao.

# scan com scripts ldap do nmap (exclui brute-force)
sudo nmap -n -sV --script "ldap* and not brute" -p 389 $TARGET

# incluir ldaps (636)
sudo nmap -n -sV --script "ldap* and not brute" -p 389,636 $TARGET
ℹ portas ldap
  • 389 - ldap (texto claro)
  • 636 - ldaps (tls)
  • 3268 - global catalog
  • 3269 - global catalog ssl

2. ldapsearch - consultas manuais

o ldapsearch e a ferramenta padrao pra consultas ldap no linux. funciona sem autenticacao em muitos ambientes mal configurados.

[!tip] ldapsearch com -z 0 (ou -s sub) pra paginacao completa. sem isso o limite default corta resultados em 1000 entries

consulta anonima (null bind)

# testar se null bind e permitido
ldapsearch -x -H ldap://$TARGET -s base

# com base dn especifico
ldapsearch -x -H ldap://$TARGET -b "DC=dominio,DC=local"

[!warning] null bind (anonymous ldap) e logado no dc. em pentest real, usar so quando autorizado. em ctf e livre

consulta autenticada

# autenticacao simples
ldapsearch -x -H ldap://$TARGET -D "dominio\\usuario" -w 'senha' -b "DC=dominio,DC=local"

# buscar todos os usuarios
ldapsearch -x -H ldap://$TARGET -D "dominio\\usuario" -w 'senha' -b "DC=dominio,DC=local" '(&(objectCategory=person)(objectClass=user))'

# usuarios com admincount (privilegiados)
ldapsearch -x -H ldap://$TARGET -D "dominio\\usuario" -w 'senha' -b "DC=dominio,DC=local" '(&(objectCategory=user)(adminCount=1))'

# usuarios com senha na descricao (voce ficaria surpreso)
ldapsearch -x -H ldap://$TARGET -D "dominio\\usuario" -w 'senha' -b "DC=dominio,DC=local" '(&(objectCategory=user)(|(description=*pass*)(description=*password*)(description=*pwd*)))'

busca de spns (kerberoasting)

# listar service principal names (pra kerberoasting)
ldapsearch -Y GSSAPI -H ldap://$TARGET -D "usuario" -W -b "DC=dominio,DC=local" "servicePrincipalName=*" servicePrincipalName

laps (senhas de admin local)

# verificar maquinas com laps ativo e ler a senha se tiver permissao
ldapsearch -x -H ldap://$TARGET -D "dominio\\usuario" -w 'senha' -b "DC=dominio,DC=local" '(ms-Mcs-AdmPwdExpirationtime=*)' ms-Mcs-AdmPwd

3. ldapdomaindump

ferramenta que faz dump completo do ad em formato html/json/grep. mais facil de analisar que output bruto do ldapsearch.

# dump completo do dominio
ldapdomaindump --no-json --no-grep -o ldap_dump -r $TARGET -u 'dominio\usuario' -p 'senha'

# com autenticacao simples
ldapdomaindump --authtype SIMPLE -o ldap_dump -r $TARGET -u 'dominio\usuario' -p 'senha'
💡 analisando o dump

o ldapdomaindump gera arquivos html que voce pode abrir no navegador. os mais uteis sao domain_users.html e domain_computers.html.

4. ldapsearch-ad (consultas avancadas)

ferramenta python focada em consultas especificas de ad.

# listar politicas de senha incluindo fgpp
ldapsearch-ad.py --server $TARGET -d dominio -u usuario -p senha --type pass-pols

# fgpp aplicada a um grupo
ldapsearch-ad.py --server $TARGET -d dominio -u usuario -p senha -t search -s '(samaccountname=grupo)' cn msDS-PSOApplied

# informacoes completas de um usuario
ldapsearch-ad.py --server $TARGET -d dominio -u usuario -p senha --type show-user -s '(samaccountname=usuario)'

5. windapsearch

alternativa em python pro ldapsearch, mais amigavel pra pentesters.

# enumerar usuarios do dominio
python3 windapsearch.py -d dominio.local --dc-ip $TARGET -u 'usuario@dominio.local' -p 'senha' --users

# enumerar grupos
python3 windapsearch.py -d dominio.local --dc-ip $TARGET -u 'usuario@dominio.local' -p 'senha' --groups

# membros do domain admins
python3 windapsearch.py -d dominio.local --dc-ip $TARGET -u 'usuario@dominio.local' -p 'senha' --da

6. netexec (nxc) - enumeracao automatizada

crackmapexec (cme) foi descontinuado em 2023. netexec (nxc) e o fork mantido e atualizado. mesma sintaxe, mais recursos.

# enumeracao ldap com null bind
nxc ldap $TARGET -u '' -p '' --users

# listar grupos
nxc ldap $TARGET -u 'usuario' -p 'senha' --groups

# buscar SPNs (kerberoasting)
nxc ldap $TARGET -u 'usuario' -p 'senha' --kerberoasting kerberoast.txt

# as-rep roastable
nxc ldap $TARGET -u 'usuario' -p 'senha' --asreproast asrep.txt
ℹ cme vs nxc

7. bloodhound - mapeamento de caminhos de ataque

bloodhound visualiza o ad como grafo e encontra caminhos de privesc (dc sync, kerberoasting, lateral movement).

# coleta de dados (legacy bloodhound-python)
bloodhound-python -d dominio.local -u user -p pass -ns $TARGET -c All

# coleta de dados (bloodhound-ce-python - community edition)
bloodhound-ce-python -d dominio.local -u user -p pass -ns $TARGET -c All
💡 bloodhound ce

bloodhound community edition (ce) e a versao atualmente mantida. usa bloodhound-ce-python pra coleta. o bloodhound-python original funciona mas nao recebe updates novos.

8. as-rep roastable - contas sem preauth

filtra contas com DONT_REQ_PREAUTH (userAccountControl bit 4194304). essas contas podem ter o as-rep extraido sem senha.

# filtro ldap pra contas sem preauth
ldapsearch -x -H ldap://$TARGET -b 'DC=dominio,DC=local' '(&(objectCategory=user)(userAccountControl:1.2.840.113556.1.4.803:=4194304))' sAMAccountName

[!warning] as-rep roasting so funciona se a conta tiver preauth desativada. e uma misconfig, nao uma vulnerabilidade padrao.

9. adcs enumeration - certificate services

active directory certificate services expoe templates de certificado que podem ser abusados (ESC1-ESC8).

# enumerar adcs com certipy
certipy find -u user -p pass -target $TARGET

# output em json e texto
certipy find -u user -p pass -target $TARGET -json
ℹ vulnerabilidades ESC1-ESC8
  • ESC1 - template com client auth e enrollee-supplied subject
  • ESC2-ESC3 - templates com any purpose ou enrollee-supplied subject
  • ESC4-ESC5 - templates com permissao de escrita abusa
  • ESC6-ESC8 - misconfig de ca, http enrolment, nt relay

10. gmsa password read - service accounts com senha gerenciada

group managed service accounts (gmsa) tem senha automatica gerenciada pelo ad. se tu tiver permissao, da pra ler.

# ler senha gmsa com certipy
certipy gMSA -u user -p pass -target $TARGET

# via powershell (windows)
# Get-ADServiceAccount -Identity "svc_account" -Properties msDS-ManagedPassword

[!tip] gmsa passwords sao blobs binarios (msDS-ManagedPassword). precisa converter pra NT hash pra usar. certipy faz isso automatico.

11. dns zones em ad - descobrir dcs internos

registros srv no dns do ad revelam domain controllers, gc, e outros servicos internos.

# descobrir dcs via srv record
dig _ldap._tcp.dc._msdcs.alvo.local SRV +short

# global catalog
dig _gc._tcp._msdcs.alvo.local SRV +short

2. nmap scanning strategies

estrategias otimizadas pra diferentes cenarios.

descoberta massiva

identifica hosts ativos sem escanear portas.

# -sn: no port scan (ping sweep)
# -PE: icmp echo request
sudo nmap -sn -iL ranges.txt -oA discovery/hosts/pingsweep -PE
⚠ nmap -sn sem root

nmap -sn sem root usa TCP probes (SYN em portas comuns) em vez de ICMP. menos confiavel que ARP. sempre rodar com sudo pra descoberta ARP.

💡 controle de velocidade

--min-rate 1000 controla velocidade sem perder hosts. --max-retries 2 evita retransmissao excessiva.

naabu (projectdiscovery)

alternativa rapida ao nmap pra port scan em massa.

# scan top 1000 portas em lista de hosts
naabu -list hosts.txt -top-ports 1000 -silent

# scan portas especificas
naabu -list hosts.txt -p 22,80,443,445,3389 -silent

# output json
naabu -list hosts.txt -top-ports 1000 -json -o naabu.json
💡 naabu vs nmap

naabu e mais rapido que nmap pra scan em massa de muitas portas. nmap ainda e melhor pra service detection e scripts NSE.

veja mais sobre nmap em nmap

port scan direcionado

escaneie as portas mais comuns nos hosts identificados.

# -Pn: ignorar ping (tratar host como online)
# -sV: versao de servico
# -A: os detection, scripts e traceroute

scan completo (todas as portas)

# scan rapido de top 100 portas

port scanning com bash e /dev/tcp

tecnica de scan de portas usando apenas bash puro, sem precisar de nmap ou qualquer outra ferramenta instalada. util quando voce tem uma shell limitada no alvo e precisa mapear a rede interna.

ℹ quando usar

em situacoes onde voce tem acesso a uma maquina comprometida mas nao pode instalar ferramentas. o bash com /dev/tcp e /dev/udp funciona na maioria dos linux.

⚠ /dev/tcp nao e universal

/dev/tcp nao existe em sh/dash. so bash compilado com --enable-net-redirections. verificar com echo $BASH_VERSION antes de usar.

💡 timeout por porta

timeout 1 por porta evita travar em portas filtradas. sem timeout, porta filtrada segura a conexao por ~60s.

1. scan basico (todas as portas)

# scan de todas as 65535 portas (demora bastante)
TARGET=10.10.10.10; for port in $(seq 1 65535); do
  bash -c "echo >/dev/tcp/$TARGET/$port" 2>/dev/null && echo "porta $port aberta"
done

2. scan rapido (portas comuns)

# scan apenas das portas mais interessantes
TARGET=10.10.10.10
for port in 21 22 23 25 53 80 110 111 135 139 143 443 445 993 995 1433 1521 2049 3306 3389 5432 5900 8080 8443; do
  (echo >/dev/tcp/$TARGET/$port) 2>/dev/null && echo "porta $port aberta"
done

3. scan com timeout

o scan basico pode travar em portas filtradas. adicione timeout pra acelerar.

# com timeout de 1 segundo por porta
TARGET=10.10.10.10
for port in $(seq 1 1024); do
  timeout 1 bash -c "echo >/dev/tcp/$TARGET/$port" 2>/dev/null && echo "porta $port aberta"
done

4. scan de multiplos hosts

# varrer um /24 nas portas mais comuns
for host in $(seq 1 254); do
  for port in 22 80 443 445 3389; do
    timeout 1 bash -c "echo >/dev/tcp/10.10.10.$host/$port" 2>/dev/null && echo "10.10.10.$host:$port aberta"
  done
done

5. scan paralelo (muito mais rapido)

# usar & pra rodar em paralelo e wait pra aguardar
TARGET=10.10.10.10
for port in $(seq 1 1024); do
  (timeout 1 bash -c "echo >/dev/tcp/$TARGET/$port" 2>/dev/null && echo "porta $port aberta") &
done
wait
⚠ cuidado com paralelo

6. alternativas sem /dev/tcp

se o bash nao tiver /dev/tcp compilado (raro, mas acontece):

# usando nc (netcat)
for port in $(seq 1 1024); do
  nc -z -w 1 $TARGET $port 2>/dev/null && echo "porta $port aberta"
done

# usando python one-liner
python3 -c "
import socket
for p in range(1,1025):
    try:
        s=socket.socket(); s.settimeout(1); s.connect(('$TARGET',p))
        print(f'porta {p} aberta'); s.close()
    except: pass
"

7. xargs -P (paralelo limpo)

mais limpo que & + wait. xargs gerencia o paralelismo automaticamente.

# scan paralelo com xargs
seq 1 1024 | xargs -P 50 -I{} bash -c \
  'timeout 1 bash -c "echo >/dev/tcp/$TARGET/{}" 2>/dev/null && echo "porta {} aberta"'
💡 xargs -P

-P 50 = 50 processos simultaneos. mais limpo que lancar & manualmente. xargs gerencia o pool de processos.

8. /dev/udp (scan UDP)

bash tambem suporta /dev/udp pra testar portas UDP. limitado porque UDP e connectionless.

# testar porta UDP
echo test >/dev/udp/$TARGET/53
⚠ UDP false negatives

UDP e connectionless. echo >/dev/udp/... nao confirma se a porta esta aberta — so que nao deu erro imediato. false negatives sao comuns. pra scan UDP confiavel, usar nmap -sU.

9. Python one-liner (fallback)

se bash nao tiver /dev/tcp e nao tiver nc, python e a alternativa mais confiavel.

# python one-liner compacto
python3 -c "import socket; [print(f'porta {p} aberta') for p in range(1,1025) if (lambda s: (s.settimeout(1), s.connect_ex(($TARGET,p)) == 0, s.close()))(socket.socket(socket.AF_INET, socket.SOCK_STREAM))]"

tcp fin fingerprint

tecnica de fingerprinting de sistema operacional baseada no comportamento da pilha tcp/ip. ao enviar pacotes tcp com flags especificas pra portas abertas, voce consegue diferenciar sistemas pela forma como eles respondem (ou nao).

metadado valor
tipo de reconhecimento ativo
nivel de ruido baixo

1. como funciona o tcp fin

a rfc 793 define que:

  • porta fechada -> deve responder com RST
  • porta aberta -> deve ignorar o pacote (nao responder)

porem, muitas implementacoes nao seguem a rfc e respondem com RST mesmo em portas abertas. isso inclui:

sistema responde rst em porta aberta?
linux nao (segue a rfc)
bsd/freebsd nao (segue a rfc)
windows sim
cisco ios sim
hp-ux sim
iris sim
ℹ o que isso significa na pratica

se voce enviar um FIN pra uma porta aberta de um servidor web e receber RST de volta, voce pode ter certeza que nao e linux nem bsd. provavelmente e windows ou cisco.

2. tcp fin simples com scapy (python)

from scapy.all import *

meu_ip = "192.168.0.10"
ip_alvo = "192.168.0.11"
porta_alvo = 80

ip1 = IP(src=meu_ip, dst=ip_alvo)
tcp1 = TCP(sport=1024, dport=porta_alvo, flags="F", seq=12345)
packet = ip1 / tcp1

p = sr1(packet, timeout=3)
if p:
    p.show()
    if p.haslayer(TCP) and p[TCP].flags == "RA":
        print("recebeu RST+ACK -> provavelmente windows/cisco")
else:
    print("sem resposta -> provavelmente linux/bsd (segue a rfc)")

3. usando nmap

o nmap tem scan types que exploram esse mesmo comportamento.

# fin scan (-sF) - envia pacotes com flag FIN
sudo nmap -sF -Pn -p 80,443 $TARGET

# xmas scan (-sX) - envia FIN+PSH+URG
sudo nmap -sX -Pn -p 80,443 $TARGET

# null scan (-sN) - envia pacote sem nenhuma flag
sudo nmap -sN -Pn -p 80,443 $TARGET

# os detection completo do nmap
sudo nmap -O $TARGET
💡 comparando resultados

rode os tres tipos de scan (fin, xmas, null) e compare com um syn scan normal (-sS). se os resultados forem diferentes, isso ja da pistas sobre o sistema operacional.

4. outras tecnicas de fingerprinting tcp

alem do fin, existem outras formas de identificar o so pela pilha tcp:

ttl (time to live)

so ttl padrao
linux 64
windows 128
cisco/network 255 
# ver o ttl de um host (o valor do ttl entrega o so)
ping -c 1 $TARGET | grep "ttl="

tcp window size

cada so usa tamanhos de janela tcp diferentes. o nmap usa isso internamente no -O.

# capturar o window size com tcpdump
sudo tcpdump -i eth0 -c 5 "host $TARGET and tcp[13] == 18" -nn

5. fingerprinting passivo com p0f

se voce quer identificar os sem enviar nenhum pacote:

#!/bin/bash
DOMAIN=$1
OUTDIR="recon/$DOMAIN/crawl"
mkdir -p "$OUTDIR"

echo "[*] coletando urls historicas..."
gau "$DOMAIN" --o "$OUTDIR/gau.txt" 2>/dev/null
waybackurls "$DOMAIN" | sort -u > "$OUTDIR/wayback.txt"

echo "[*] crawl ativo..."
<a class="internal-link" data-target="-f live_subs.txt" href="#-f live_subs.txt">-f live_subs.txt</a> && katana -list live_subs.txt -d 2 -silent -o "$OUTDIR/katana.txt"
katana -u "https://$DOMAIN" -d 2 -silent -o "$OUTDIR/katana_root.txt"

echo "[*] juntando e filtrando..."
cat "$OUTDIR/gau.txt" "$OUTDIR/wayback.txt" "$OUTDIR/katana.txt" "$OUTDIR/katana_root.txt" 2>/dev/null | sort -u > "$OUTDIR/all_urls.txt"
cat "$OUTDIR/all_urls.txt" | grep "=" | sort -u > "$OUTDIR/params.txt"
cat "$OUTDIR/all_urls.txt" | grep -E "\.js$|\.js\?" | sort -u > "$OUTDIR/js_files.txt"
cat "$OUTDIR/all_urls.txt" | grep -iE "api|graphql|v1|rest" | sort -u > "$OUTDIR/api.txt"

echo "[*] baixando js e scan de secrets..."
mkdir -p "$OUTDIR/js"
cat "$OUTDIR/js_files.txt" | getJS --complete --resolve --output "$OUTDIR/js/" 2>/dev/null
grep -rlnE "api[_-]?key|secret|token|password|aws_|firebase" "$OUTDIR/js/" > "$OUTDIR/js_secrets.txt" 2>/dev/null

echo "[+] $(wc -l < "$OUTDIR/all_urls.txt") urls"
echo "[+] $(wc -l < "$OUTDIR/params.txt") com parametros"
echo "[+] $(wc -l < "$OUTDIR/js_files.txt") arquivos js"
echo "[done] resultados em $OUTDIR/"
